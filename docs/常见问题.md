# 常见问题

## 安装与启动

### 双击 `启动工作台.cmd` 一闪就没了

多半是没装 Node.js。请装 [Node.js 18+](https://nodejs.org/) 后重开一次。
这个 `.cmd` 的内容刻意是纯英文的 —— cmd.exe 按系统 ANSI 代码页解析 `.cmd` 文件，
里面写中文会变成乱码，所以中文说明都放在这里。

### 端口被占

工作台默认 `8030`，被占会自动往后顺延到第一个能用的端口，启动时终端里会打印实际地址。
也可以指定：`node server/server.mjs --port 9000`。

### 需要联网吗

不需要。工作台只在探测阶段读一次本机的 ComfyUI `/system_stats`（就是 `127.0.0.1:8188`）。
不装插件、不下模型、不上传任何数据。你填的配置只写在本机 `data/profile.json`（已在 `.gitignore` 里）。

## 探测相关

### 显存/显卡探测不出来

只有装了 NVIDIA 驱动（带 `nvidia-smi`）才能自动读到显存总量。
读不到时工作台**不会猜**，会让你手填 —— 这是故意的：猜错显存会让整套推荐错位。

AMD / Intel 显卡：工作台只做定性识别，给一份自查清单，不出具体档位。
原因很简单：本项目没有在 A 卡或核显上实测过任何一条链路，按 N 卡的档位给建议是害人。

### 内存显示得比标称少（例如标称 16 GB 显示成 15.x GB）

正常。`os.totalmem()` 读的是操作系统可用总量，核显预留、BIOS 保留都会扣掉一点。

### 探测到的 ComfyUI 路径不对

它只扫常见位置（`D:\ComfyUI`、`%USERPROFILE%\ComfyUI`、ComfyUI Desktop 的安装目录等），
并且要求目录下同时有 `main.py` 和 `models`。扫不到就手填，填含 `main.py` 的那一层。

## 方案与清单

### 为什么清单里同一个位置有好几套权重，工作台只让我下一套

因为**工作流 JSON 里本来就写着好几套**。作者为了兼容不同显存，把 int8、NVFP4、GGUF 三条路线的
加载节点都画进了同一份图，靠旁路开关切换。

不过滤的话，8G 卡的用户会被要求下 142 GB。工作台的做法是：
识别出「同槽位互斥变体」，按档位选一套，其余的列在「同槽位备选（先别下）」里。

⚠️ 但有一条限定：**只有「被同一组工作流引用」的变体才算互斥**。
反例是反推流图点名的 9B 大模型和视频图点名的 4B 大模型 —— 它们同属一个槽位，
但图里是写死文件名的，当成互斥删掉图就废了。这种情况两套都会保留。

### 清单里的体积有的写着「约」，有的写着「未知」

- 数字 = 有实测记录（来自原部署脚本）；
- 「约 X GB」= 按同结构权重线性折算的估算，鼠标悬停或看 `catalog/models.meta.json` 里的 `sizeBasis` 能看到推算依据；
- 「未知」= 真的不知道，以实际下载为准。**磁盘规划按实际为准。**

### 「需你搜索」是什么意思，为什么不直接给下载链接

这些插件/权重来自社区整合包，仓库地址会变、会被删、会有多个同名不同版。
写一个没核对过的地址比不写更糟 —— 用户照着 clone 一个错的仓库，浪费的是他的时间。

所以工作台的做法是：给出**精确文件名** + **它提供的节点名**（这两个足够独特，一搜就中），
然后让你自己的 agent 去搜、去核对、去重试。生成的那段提示词就是为这个场景写的。

GitHub 上标「地址可靠」的那些，要么能在工作流 JSON 里找到直链证据，要么来自原部署脚本的实测记录。

### 提示词交给谁

任何能读写文件、能跑命令的 agent 都行：Claude Code、Codex、Cursor、Gemini CLI、你自己的 DSH 都行。
整段复制粘贴即可，里面已经写清了环境事实、精确文件名、目标目录、验证方法和禁止事项。

## 导入相关

### 一键导入为什么不覆盖已有文件

因为 `<ComfyUI>/user/default/workflows/` 里那份同名图很可能已经被你自己改过了。
要覆盖就勾上「覆盖已存在的同名文件」或加 `--overwrite`。

### 导入时说「这看起来不是 ComfyUI 的根目录」

工作台要求目标目录下同时存在 `main.py` 和 `models/`，否则拒绝写入。
这不是刁难 —— 防的是把工作流复制到某个手滑填错的地方。

### 图导进去了，但一屏红框

说明缺插件。**可靠的查法**：

1. 拉 `http://127.0.0.1:8188/object_info`，取它所有的 key；
2. 与工作流里的节点类型求差集，剩下的就是缺的；
3. 装完对应的 custom_nodes，重启 ComfyUI，再看启动日志里有没有 import 失败。

工作台预判的「未被插件清单覆盖的节点」也会列在方案页最下面。

### 模型下好了，但节点下拉框里选不到

九成是**目录名对不上**。工作流里存的是相对 `models/` 的子路径，
比如 `Minimax_H3/nvfp4/MiniMax-H3_FL2VA-NVFP4-HQ.safetensors`，
那文件就必须落在 `models/Minimax_H3/nvfp4/` 下，子目录名一字不差（含大小写、空格、下划线）。

`node tools/build-catalog.mjs --check` 会校验这一点。

还有一个特例：`models/LLM/` **原版 ComfyUI 没有这个目录**，是 `comfyUI-llama-TE`
插件运行时注册的。放进这个目录的文件必须**物理位于那里**，
写进 `extra_model_paths.yaml` 会被静默丢弃。

## 跑图相关

### 8G 显存跑 H3 视频要注意什么

- 给 ComfyUI 加启动参数 `--lowvram`；
- 清晰度与时长**二选一**：高清晰度就把时长压到 5 秒，要长时长就把清晰度压到 0.6MP 以下；
- 同一时间只开一个本地大模型服务，别和 ComfyUI 抢内存；
- 先跑 0.6MP / 3 秒的小样确认不爆，再往上加。

### 换了 NVFP4 之后快了多少

参考机实测：**41%**（1.0MP × 5 秒从 415 秒降到 245 秒）。
文本编码器换 NVFP4 **不影响采样速度**（只在提示词编码阶段用），但省约 9.6 GB 磁盘、加载更省内存。

### 装 LayerStyle 之后启动日志报 `Cannot import name 'guidedFilter' from 'cv2.ximgproc'`

装了 `opencv-python-headless` 就会这样。只有锐化/边缘蒙版那几个节点受影响，
反推流用到的 `ImageScaleByAspectRatio V2` 不碰它。
要全功能就装 `opencv-contrib-python`（会和 headless 版抢 `cv2/` 目录，想清楚再装）。

## 仓库维护

### 我加了一份新工作流，要做哪些事

1. 丢进 `workflows/`；
2. 跑 `node tools/build-catalog.mjs` —— 它会告诉你**缺哪几个权重的注记**，一个个补进 `catalog/models.meta.json`；
3. 在 `catalog/workflows.meta.json` 里加这条工作流的标题、用途、分级、目标、最低档位；
4. 跑 `npm run check`，全绿再提交。

如果新图用到了新插件，在 `catalog/plugins.meta.json` 里加一条；
`uncovered-nodes.json` 会告诉你还有哪些节点没被覆盖。

### 为什么 `catalog/*.json` 是生成物还要提交

为了「clone 下来就能直接跑」。否则第一次 `npm start` 会因为读不到 `catalog/models.json` 直接失败。
`npm run check` 会持续校验这些生成物与 `workflows/` 是否同步。
