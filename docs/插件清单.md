# 插件清单（ComfyUI custom_nodes）

这些是 **ComfyUI 的插件**，不是工作台自己的插件。工作台零依赖，不需要装任何东西。

`覆盖节点数` 是这个插件在 `workflows/` 里被实际用到的节点类型数量 —— 数字越大，缺了它红框越多。

**「地址可靠」= 仓库地址经过核对，可以直接 clone；「需你搜索」= 只知道它提供的节点名，
必须让你自己的 agent 先搜到仓库、确认存在，再 clone。**这是刻意的设计：这几批节点随整合包分发，
写死一个没核对过的地址比不写更糟。

## 需要搜索的那些，怎么搜

### comfyUI-llama-TE

- 提供的节点：`llama_cpp_model_loader`、`llama_cpp_instruct_adv`、`LLAMACPPARAMS`、`LLAMACPPMODEL`、`QWENLLAMA`
- 搜索线索：原名 comfyUI-llama-TE，随夸克整合包分发。让 agent 在 GitHub 搜 llama-TE / llama_cpp_model_loader，确认仓库存在再 clone；同时确认它注册的模型目录名是 LLM。
- 注意：⚠️ models/LLM 这个目录是它运行时注册的，不写进 extra_model_paths.yaml（写了会被静默丢弃）。

### MiniMax-H3-节点包（整合包内）

- 提供的节点：`MiniMaxH3ImageToVideo`、`MiniMaxH3ReferenceToVideo`、`MiniMaxChunkFeedForward`、`MiniMaxH3SigmaShift`、`MiniMaxLowVRAMAttention`、`MiniMaxH3ContextLatentTaperNoise`、`MiniMaxH3MotionContextClipStream`、`MiniMaxH3MotionContextTrimClipStream`、`MiniMaxH3EasyLatentUpscaler3D`、`MiniMaxH3TwoPassLatentReconcileT8Advanced`、`MiniMaxH3LatentUpscaleBy32T8`、`MiniMaxClipBinDualPicker`、`MiniMaxClipBinDualSaver`、`MiniMaxClipBinPicker`、`MiniMaxClipBinSaver`、`MiniMaxClipBinLongBuilder`、`MiniMaxH3MemoryEfficientSageAttentionPatch`、`MMH3LatentUpscaleWithModelParams`、`MMH3SpatialSplitParams`、`MMH3TemporalSplitParams`、`MMH3UltimateUpscale`、`H3 Segment Picker`、`H3 Long Video Manager`、`H3SigmaRefiner`、`minimax`、`ModelAttentionBackend`、`ReservedVRAMSetter`
- 搜索线索：来源是 B 站 UP 主的夸克整合包（工作流 JSON 内留有 pan.quark.cn/s/ca4e2a25b3e4 与 space.bilibili.com/36380937 两个链接）。让 agent 先确认新版 ComfyUI 是否已内置同名节点：用 /object_info 比对，已内置的就不必装。仍未覆盖的再从整合包或 GitHub 上找对应节点包。
- 注意：⚠️ 这批节点名与新版 ComfyUI 内置的 MiniMax 节点有重叠。判断方法只有一个：把工作流导入后看红框，或拿 /object_info 求差集。

### TE_MAN / TE-Speed-MiniMaxH3

- 提供的节点：`QwenTE_ModelLoader`、`QwenTE_ImageInfer`、`TE_H3_Prompt_Enhancer`、`TE_prompt_text`、`TE_H3_REFERENCES`、`TE_text_display`、`TESpeedMiniMaxH3`
- 搜索线索：TE_MAN 与 TE-Speed-MiniMaxH3 是整合包内的两个目录名。让 agent 搜 QwenTE_ModelLoader / TESpeedMiniMaxH3 这两个独特的节点名定位仓库。

### ComfyUI-SolAttn_triton

- 提供的节点：`BlockSparseAttention`
- 搜索线索：搜 SolAttn / BlockSparseAttention 节点名。⚠️ 不装 triton-windows 这个插件会整个 import 失败。
- 注意：⚠️ 依赖 triton-windows，Windows 上装不上就整个插件不可用（不影响其它功能）。

### comfyui-krea2edit

- 提供的节点：`Krea2EditGroundedEncode`、`Krea2EditModelPatch`
- 搜索线索：搜 krea2edit / Krea2EditGroundedEncode 节点名定位仓库。

### ComfyUI-SeedVR2_VideoUpscaler

- 提供的节点：`SeedVR2LoadDiTModel`、`SeedVR2LoadVAEModel`、`SeedVR2VideoUpscaler`
- 搜索线索：搜 SeedVR2VideoUpscaler 节点名。ByteDance 的 SeedVR2 有多个 ComfyUI 移植版，选 star 多、近期有更新的那个。

### 动漫反推流定制节点包（Danbooru / Anima 系）

- 提供的节点：`DanbooruBrowser`、`DanbooruTagClassifier`、`DanbooruTagDedup`、`DanbooruTagPreview`、`DanbooruText`、`DanbooruTextAdvanced`、`DanbooruTextConcat`、`DanbooruTextPassthrough`、`DanbooruNodeBypass`、`AnimaDexBrowser`、`AnimaPromptConverter`、`TagMapper`、`TTResolutionSelector`、`Comfly_LLm_API`、`Lora Loader (LoraManager)`、`GroupIgnoreManager`
- 搜索线索：这批节点来自反推流整合包。让 agent 逐个搜 DanbooruTagClassifier / AnimaPromptConverter / TTResolutionSelector 这几个独特节点名；Comfly_LLm_API 一般出自 ComfyUI-Comfly 之类的第三方 LLM 节点包。
- 注意：只有跑「动漫通用反推流」才需要；只玩视频的可以跳过。

### 其它零散第三方节点

- 提供的节点：`JWImageResizeByLongerSide`、`VRGDG_VideoCompareSlider`、`FloatConstant`、`INTConstant`、`Latent Size to Number`、`ManualSigmas`、`SplitSigmas`、`VideoCombineV2`、`H3_SPATIAL_PARAM`、`H3_TEMPORAL_PARAM`、`H3_UPSCALE_PARAM`
- 搜索线索：逐个搜节点名。这类节点缺了通常只影响某一个辅助功能，不影响主链路；H3_*_PARAM 三个应属 MiniMax H3 节点包，跟着它一起装。

## 没被任何插件覆盖的节点

工作流里用到、但既不是 ComfyUI 自带、也没有匹配到上面任何插件的节点类型：

- `krea2`（出现在 1 份图里）
- `qwen_image`（出现在 1 份图里）

多数是整合包里的零散辅助节点，导入工作流后看红框即可确认；
用 `/object_info` 的 key 集合与工作流的节点类型求差集，是最可靠的查法。
